How it works

Broadcast in. Probability out.

01 / FRAME

Capture

Glasses camera samples 1–2 sharp frames per second from the screen you're watching.

02 / VISION

Read

Vision model parses the scoreboard into schema-locked JSON: teams, score, period, clock.

03 / STATE

Reconcile

Temporal invariants reject replays, cuts, and OCR noise. Scores never go backwards.

04 / MODEL

Estimate

Deterministic win-probability engine turns state into a calibrated, bounded estimate.

05 / MARKET

Compare

Polymarket adapter pulls the live market-implied price. The gap is the signal.

END-TO-END TARGET: TRUSTED UPDATE WITHIN 2–5 SECONDS OF A STABLE STATE CHANGE

Under the hood

Small, sharp,
and built to demo.

Every layer sits behind an explicit interface: swap the camera, the model, or the market provider without touching the rest.

A

Zero-dependency Node core

One process, typed contracts between every stage. Nothing to install, nothing to break on stage.

B

Gemini vision, schema-locked

Frames in, structured scoreboard JSON out, with per-field confidence scores.

C

Deterministic probability models

Explainable per-sport engines: bounded, monotonic, scenario-tested. No black box.

D

Polymarket adapter + iOS app

Live market-implied prices behind a clean adapter; a companion app carries the glasses experience.

E

Training-data flywheel

Every session logs frame → state → outcome. Usage itself builds the dataset that sharpens the models.
